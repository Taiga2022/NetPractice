# NetPractice 課題ガイド

## 1. 課題の目的

NetPractice は、IPv4 ネットワークの基礎を身につけるための演習です。

プログラムを書く課題ではありません。ブラウザ上のネットワーク図を見ながら、次の値を正しく設定し、指定された機器同士を通信可能にします。

- インターフェースの IPv4 アドレス
- サブネットマスク
- ルーティングテーブルの宛先ネットワーク
- ゲートウェイ

演習は Level 1〜10 の全10レベルです。後半になるにつれて、Host、Switch、Router、Internet を組み合わせた複雑な構成になります。

> 画面に登場するネットワーク構成やアドレスは架空のもので、実際のネットワークには接続されていません。

## 2. 最終的に必要なこと

1. NetPractice を起動する
2. Training モードで Level 1〜10を解く
3. 各レベルですべての Goal を `OK` にする
4. 各レベルの設定を JSON ファイルとして保存する
5. `level1.json`〜`level10.json` の10ファイルを提出する

Cソース、Makefile、実行ファイルなどを作成する課題ではありません。

## 3. 起動方法

このリポジトリでは、次のコマンドで起動できます。

```bash
cd net_practice
bash run.sh
```

ローカルWebサーバーが起動し、通常はブラウザが自動的に開きます。自動的に開かない場合は、ターミナルに表示されたURLをブラウザで開きます。

```text
http://localhost:49242
```

ポート番号は、使用状況によって変わることがあります。終了するときは、サーバーを実行しているターミナルで `Ctrl-C` を押します。

## 4. Training モードの進め方

1. 最初の画面で `Training` を選ぶ
2. 42のログイン名を入力する
3. `Start!` を押す
4. 白い入力欄の値を修正する
5. `Check again` で通信を確認する
6. すべての Goal が `OK` になったら `Get my config` で設定を保存する
7. `Next level` で次へ進む

ログイン名を基に問題の数値が生成されるため、通常は同じログイン名なら同じ構成になります。固定表示されている値は変更できず、白い入力欄だけ編集できます。

### Goal とログ

`Check again` を押すと、各通信目標に次の状態が表示されます。

- `OK`: 必要な双方向通信が成立している
- `KO`: 通信経路のどこかに問題がある

画面下部のログを開くと、パケットがどの機器を通り、どこで止まったか確認できます。

代表的な失敗原因は次のとおりです。

- IPアドレスまたはマスクの形式が不正
- 直接接続された両端が同じサブネットにない
- IPアドレスが重複している
- ネットワークアドレスまたはブロードキャストアドレスをHostに割り当てている
- ゲートウェイが送信元インターフェースから直接到達できない
- 宛先に一致するルートがない
- 戻りのルートがない
- Internetへプライベートアドレスをそのままルーティングしている

## 5. 機器の役割

### Host

通信の開始地点・終了地点になる端末です。通常、IPアドレス、サブネットマスク、デフォルトルート、デフォルトゲートウェイを設定します。

### Switch

同じLAN内の機器を接続します。NetPracticeではSwitch自身のIP設定は通常不要です。同じSwitchにつながるHostやRouterのポートは、原則として同一サブネットに所属させます。

### Router

異なるネットワーク同士を接続します。各インターフェースは、それぞれの接続先ネットワークに属するIPアドレスを持ちます。直接接続されていない宛先へ通信するにはルーティングテーブルが必要です。

### Internet

外部ネットワークを表します。外部へ出る経路だけでなく、外部から内部へ戻るためのルートも必要です。

## 6. レベル別の学習内容

問題中の具体的な数値はログイン名によって変わるため、答えの丸暗記ではなく計算方法を理解する必要があります。

### Level 1：同一ネットワークの基本

2組のHostをそれぞれ通信可能にします。

- 直接接続された2台を同一サブネットにする
- IPアドレスを重複させない
- マスクからネットワーク範囲を判断する

### Level 2：IPアドレスとマスク

IPアドレスとサブネットマスクの両方を調整します。

- CIDR表記とサブネットマスクの対応
- 同一ネットワークの判定
- ネットワークアドレス、Host範囲、ブロードキャストアドレスの計算

### Level 3：Switchと複数Host

3台のHostが1台のSwitchにつながっています。3台すべてを同一サブネットに所属させ、互いに通信可能にします。

```text
Host A ─┐
Host B ─┼─ Switch
Host C ─┘
```

### Level 4：Routerの複数インターフェース

Host、Switch、Routerが登場します。

- Switchは同じネットワーク内を接続する
- Routerは異なるネットワークを接続する
- Routerの異なるポートに重複するネットワークを割り当てない
- 各リンクの両端を同一サブネットにする

### Level 5：デフォルトルート

2台のHostをRouter経由で通信させます。

- Hostのデフォルトルートを設定する
- 直接到達できるRouterのIPをゲートウェイにする
- 行きと戻りの両方の経路を成立させる

### Level 6：Internetへの接続

HostからRouter経由でInternet上の宛先へ通信します。

- Hostのデフォルトルート
- HostとRouter間のサブネット
- RouterからInternet側への経路
- Internet側から内部ネットワークへの戻りルート

### Level 7：Router同士の通信

2台のRouterを経由してHost同士を通信させます。

```text
Host A ─ Router 1 ─ Router 2 ─ Host C
```

少なくとも次の3ネットワークに分けて考えます。

1. Host AとRouter 1のネットワーク
2. Router 1とRouter 2の中継ネットワーク
3. Router 2とHost Cのネットワーク

### Level 8：複数RouterとInternet

内部Host同士の通信と、各HostからInternetへの通信を同時に成立させます。

- 各物理リンクのサブネット
- Router同士の中継ネットワーク
- Hostのデフォルトゲートウェイ
- Routerの内部ネットワーク向けルート
- Internet側の戻りルート

### Level 9：総合ルーティング

複数のHost、Switch、Router、Internetが登場します。

- 同一LAN内の通信
- Routerをまたぐ通信
- 複数の重複しないサブネット
- 個別ルートとデフォルトルート
- Internetへの往復経路

必要以上に広いマスクを設定すると、本来Routerへ渡すべき宛先を同一LAN内にあると誤認するため注意します。

### Level 10：最終総合問題

Level 9と同様の総合問題ですが、通信目標がさらに増えます。Goalごとに場当たり的に直すのではなく、最初に物理リンクとサブネットを整理してから設定します。

## 7. サブネット計算

### CIDRとサブネットマスク

| CIDR | サブネットマスク | アドレス数 |
|---:|---|---:|
| `/8` | `255.0.0.0` | 16,777,216 |
| `/16` | `255.255.0.0` | 65,536 |
| `/18` | `255.255.192.0` | 16,384 |
| `/20` | `255.255.240.0` | 4,096 |
| `/22` | `255.255.252.0` | 1,024 |
| `/23` | `255.255.254.0` | 512 |
| `/24` | `255.255.255.0` | 256 |
| `/25` | `255.255.255.128` | 128 |
| `/26` | `255.255.255.192` | 64 |
| `/27` | `255.255.255.224` | 32 |
| `/28` | `255.255.255.240` | 16 |
| `/29` | `255.255.255.248` | 8 |
| `/30` | `255.255.255.252` | 4 |
| `/31` | `255.255.255.254` | 2 |
| `/32` | `255.255.255.255` | 1 |

通常のHost用サブネットでは、先頭がネットワークアドレス、末尾がブロードキャストアドレスになるため、Hostには使用できません。

### ブロックサイズ

変化するオクテットのブロックサイズは、次の式で求められます。

```text
ブロックサイズ = 256 - マスクの値
```

`/26` の場合は次のようになります。

```text
Mask: 255.255.255.192
256 - 192 = 64
```

したがって、サブネットは64刻みです。

```text
192.168.1.0   ～ 192.168.1.63
192.168.1.64  ～ 192.168.1.127
192.168.1.128 ～ 192.168.1.191
192.168.1.192 ～ 192.168.1.255
```

`192.168.1.70/26` の範囲は次のとおりです。

```text
Network:    192.168.1.64
Host範囲:   192.168.1.65 ～ 192.168.1.126
Broadcast:  192.168.1.127
```

### 同一ネットワークの判定

IPアドレスとサブネットマスクのAND演算でネットワークアドレスを求めます。

```text
IPアドレス AND サブネットマスク = ネットワークアドレス
```

2つのIPについて結果が同じなら、同一ネットワークです。直接接続されたリンクの両端は、互いを同一ネットワークと判定できる必要があります。

## 8. ルーティング

### ルートの読み方

ルートは次の意味を持ちます。

```text
宛先ネットワーク => 次に渡すRouterのIP
```

例：

```text
10.0.0.0/8 => 192.168.1.254
```

宛先が `10.0.0.0/8` に含まれる場合、パケットを `192.168.1.254` に渡します。

### デフォルトルート

どの個別ルートにも一致しない通信に使います。

```text
0.0.0.0/0
```

画面によっては `default` と表示・入力されます。

NetPracticeのシミュレーターはルートを上から順番に調べ、最初に一致したルートを使います。一般に、具体的なルートを先、デフォルトルートを最後に考えます。

### ゲートウェイの条件

ゲートウェイは、設定元のインターフェースから直接到達可能なIPでなければなりません。

```text
Host:    192.168.1.10/24
Gateway: 192.168.1.254
```

この例では、HostとGatewayがともに `192.168.1.0/24` に所属するため、直接パケットを渡せます。

### 往復経路

通信には行きと戻りの両方のルートが必要です。

```text
送信元 → Router → 宛先
送信元 ← Router ← 宛先
```

片方向の設定だけ正しくてもGoalは `OK` になりません。特にInternetを含むレベルでは、Internet側の戻りルートを忘れないようにします。

## 9. 問題を解く手順

1. 物理リンクごとにネットワークを分ける
2. 変更できないIPアドレスとマスクを確認する
3. 固定値からネットワーク範囲を計算する
4. 各リンクの両端を同一サブネットにする
5. ネットワークアドレスとブロードキャストアドレスを避ける
6. IPアドレスの重複を避ける
7. Hostのデフォルトゲートウェイを設定する
8. Routerに宛先ネットワークへのルートを設定する
9. 戻り経路も設定する
10. `Check again` を押す
11. `KO` になったGoalのログを確認する
12. 全Goalが `OK` になったら設定を保存する

## 10. 設定ファイルと提出物

各レベルを解いたら `Get my config` を押します。次のファイルがダウンロードされます。

```text
level1.json
level2.json
...
level10.json
```

同じレベルを複数回ダウンロードすると、ブラウザが次のように名前を変える場合があります。

```text
level1 (1).json
```

提出時には、必ず `level1.json` の形式に戻します。提出用リポジトリのルートには、次の10ファイルを配置します。

```text
NetPractice/
├── level1.json
├── level2.json
├── level3.json
├── level4.json
├── level5.json
├── level6.json
├── level7.json
├── level8.json
├── level9.json
└── level10.json
```

## 11. 評価への準備

この演習に含まれるEvaluationモードでは、Level 6〜10からランダムに3レベルが出題され、制限時間は15分です。

評価までに、次の操作を短時間でできるようにします。

- サブネット範囲を計算する
- 同一ネットワークか判定する
- 使用可能なHostアドレスを選ぶ
- デフォルトゲートウェイを設定する
- Router間の経路を設計する
- Internetを含む往復ルートを設定する
- ログから通信が止まった場所を特定する

Trainingを一度終えるだけでなく、Evaluationモードを複数回練習しておくと安心です。

## 12. 提出前チェックリスト

- [ ] Level 1〜10をすべて解いた
- [ ] 各レベルですべてのGoalが `OK` になった
- [ ] 各レベルで `Get my config` を押した
- [ ] `level1.json`〜`level10.json`がそろっている
- [ ] ファイル名に `(1)` などが付いていない
- [ ] JSONファイルが空ではない
- [ ] 10ファイルを提出用リポジトリのルートに置いた
- [ ] Git管理されている提出用リポジトリでcommitとpushを完了した
- [ ] EvaluationモードでLevel 6〜10を練習した

## まとめ

この課題で必要なのは、ネットワーク図を物理リンクごとのサブネットに分け、各インターフェースのIPアドレスとマスクを決め、すべての通信に対する往復ルートを設定することです。全10レベルの設定をそれぞれJSONとして保存し、その10ファイルを提出します。
